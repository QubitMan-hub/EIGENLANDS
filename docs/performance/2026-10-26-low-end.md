# Low-end desktop performance — 2026-10-26

Goal: keep the game playable on any PC, including integrated or very weak GPUs.

**How it was measured.** `e2e/desktop-performance.mjs` profiles the production solo build at 1366×768, DPR 1, with
mouse input. It runs three scenes: Hadamere, the Aurelion capital and open wilderness. In each scene it walks a square
and records:

- frame intervals;
- the game's own frame work;
- long tasks;
- a sampled CPU profile.

Chromium ran with the SwiftShader software GPU. That makes rendering GPU-bound, much like a weak integrated GPU, so the
numbers compare runs on the same machine; they are not real-hardware results.

## Where the time went

Isolating each pass showed what dominated the frame:

1. terrain repaint (the ray-marched shader at art resolution);
2. the lighting multiply;
3. sprite drawing;
4. a fixed per-frame base cost.

## Changes

- **Performance tier.** The canvas backing store draws one pixel per art pixel, and the browser upscales it with
  nearest-neighbour (`image-rendering: pixelated`), so framing and pixel art look the same. In this tier:
  - the terrain uses a wide overscan (`TERRAIN_PAD_WIDE`), so it repaints less often while walking;
  - terrain motion (water ripples, swaying grass) is frozen.
- **Adaptive Auto.** `AdaptiveQuality` watches the median frame interval:
  - **Step down** (High → Economy → Performance) after sustained frames slower than 33 ms.
  - **Step up** only after 30 s of headroom.
  - **No oscillation:** a tier abandoned twice is never retried.
  - **Ignored samples:** hidden-tab gaps over 2.5 s.
  - **Notice:** a toast explains each step.

  The Settings select offers Auto, High, Economy and Performance.

- **Daylight lighting skip.** The half-resolution lightmap pass is skipped entirely when ambient light is at least
  0.98, which covers most of the day.
- **Cheaper villager sheets.** They build only the walk columns until a combat or harvest pose is actually needed.
- **Faster A\* routes.** A\* uses numeric keys and a binary heap; the old string keys and linear scan were O(n²) on long
  town routes.

## Results (same software GPU, before → after)

| Scene            | FPS       | Median frame interval |
| ---------------- | --------- | --------------------- |
| Hadamere         | 1.3 → 5.9 | 767 ms → 117 ms       |
| Wilderness       | 1.4 → 9.2 | 717 ms → 83 ms        |
| Aurelion capital | 1.4 → 3.9 | —                     |

With Auto selected, the same machine settles on Performance at 11–14 fps, where it previously ran at 2–3 fps.

These figures show relative gains on a software renderer. They are not a frame-rate promise for any particular
computer. Real integrated GPUs are typically many times faster than SwiftShader.

## Reproduce

```
node e2e/desktop-performance.mjs <solo-url> <out-dir> --graphics=auto|high|economy|performance [--frames-only]
```

Run it on an otherwise idle machine. `visual-budget.test.ts` covers tier resolution, the step-down/step-up sequence
and a 2 fps machine.
